# Terminal (step 12)

## What
- /terminal: a full-screen trader workspace with four preset layouts (Market, Monitor, Cross-venue, Catalysts) chosen by `?layout=`. The contract in focus is set by `?m=venue:id`, so any view can be shared as a link.
- Panels: market monitor, price chart, order book, depth and liquidity, trade tape, ticket, Manta's fair value with its track record, every outcome of the event, cross-venue arbitrage sized by walking both books after fees, implied distribution, catalyst calendar, alerts.
- Books and trades are polled every 2 s through one read-only route (`/api/live`) and shared by every live panel. The other panels re-render from the server every 15 s. Cmd-K command bar to jump to any market or layout.
- lib/book.ts (depth near the mid, imbalance, cumulative depth) and lib/arb.ts (arbitrage size after fees), with tests.
- Fix: every page discarded its server HTML and the terminal reloaded itself every 1-2 s (React #419). components/ClerkFirst.tsx loads Clerk's client code before its provider renders. Rule added to AGENTS.md.
- Fix: the order book listed asks from the top and was cut off by the panel, hiding the best ask and every bid. It now centres the spread row when the book first loads.

## Why
Step 12 in docs/product.md: one screen with everything a trader checks before acting on a contract, built from data the site already has.

## Decisions
- Preset grid layouts and a command bar instead of drag-and-drop panels: no new dependency, and every layout can be shared as a URL (Carson, 2026-11-22).
- Polling every 2 s instead of WebSockets for now. The WebSocket relay is its own worktree ("relay").
- The fair-value panel shows Manta's Brier score (accuracy score, lower is better) next to the market's, with a plain verdict. Our own data shows no measurable edge over Kalshi's mid, so it is labelled a second opinion, never a buy signal.
- Signed-out alerts show a sign-in link, not Clerk's button: the button can't render on the server inside the client live-data wrapper.
