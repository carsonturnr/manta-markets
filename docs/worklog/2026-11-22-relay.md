# 2026-11-22 relay

## What
- `recorder/internal/relay`: keeps each Kalshi market's book and latest 20 trades in memory from the recorder's own writes (`rawlog.Writer.OnWrite`, through `internal/normalize`), and pushes changes over Server-Sent Events, coalesced to at most one push per market every 250 ms.
- Endpoints (bearer `RELAY_TOKEN`, GET only): `/stream?tickers=A,B` (≤ 50 tickers, ≤ 100 streams) and `/health` (records, dropped, slow, markets, clients).
- Message: one `data:` line per changed market, the market's whole state: `{"ticker","live","t" (unix ms),"bids":[[px,sz]…],"asks":[[px,sz]…],"trades":[{"t","side","px","sz"}…]}`; dollars and contracts, best first, YES side, trades newest first. `live:false` means the book may have missed an update: no levels until Kalshi's next snapshot.
- `cmd/recorder`: `-relay-addr` (off when empty) and `-relay-every`. `replay.Apply`/`replay.Top` exported for reuse.

## Why
Step 12: the terminal's books and trades update live instead of being polled every 2 s.

## Decisions
- SSE over WebSockets: one-way data, plain HTTP a Next route can pipe through, automatic reconnect, standard library only.
- Inside the recorder, not a separate service: the records are already in memory; the hook never blocks, and a relay panic stops only the relay.
- Whole state per push, not deltas: the client replaces what it had; a missed push is harmless.
- Cost (busiest hour, 26.3 M records, on the Mac): +3.9% of one core, 20–36 MB heap; see docs/decisions.md.

## Deploy plan (needs Carson's go-ahead)
1. Generate RELAY_TOKEN (32+ chars), add to /etc/manta/env and Vercel (server-only env, with RELAY_URL).
2. Add `-relay-addr :8791` to manta-recorder.service, `deploy.sh`, which restarts the recorder (a gap of a few seconds, logged).
3. `ufw allow 8791/tcp`; check `/health` and `ps` CPU/RSS against the 29% baseline for a day.
4. Site (terminal worktree): `app/api/live/stream/route.ts` validates tickers, fetches `${RELAY_URL}/stream?tickers=…` with the token, returns the body as `text/event-stream`; `Live.tsx` uses `EventSource` for Kalshi, keeps `/api/live` polling for Polymarket and as the fallback while `live` is false.

## Follow-ups
- Token and data travel as plain HTTP, as with replayserve: put both behind TLS (e.g. Caddy) before the API (step 12) is public.
- Vercel functions stop streams at their maximum duration; EventSource reconnects and gets current state, but cost should be checked.
- Pre-existing: replay's Builder ignores a seq gap without a market ID (the tap reconnects at once, so the window is short).
