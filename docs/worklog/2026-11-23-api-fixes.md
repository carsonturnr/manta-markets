# API fixes from the step 13 demo

## What
- `/api/v1/cost` checks the key and rate limit before the query: no valid key → 401, even with a
  bad query. The other four routes already did; they read no query that can fail.
- `/account`: the one-time "Copy this key now" box disappears once that key is deleted (or is
  otherwise gone from the list). `createKey` now returns the new key's id; `KeyForm` shows the
  key only while that id is still listed.
- `/cost` rounds its output: `value`, `fee`, `total` to the venue's fee precision ($0.0001
  Kalshi, $0.00001 Polymarket); `best_price`, `average_price`, `slippage`, `per_contract` to 6
  decimals. lib/cost.ts is unchanged. Documented on /docs/api.
- Tests in lib/api.test.ts: rounding on a Kalshi walk with float noise and a Polymarket walk.

## Why
Found in the live demo on 2026-11-23: an unauthenticated /cost with a bad query got 400, the
shown key stayed on screen after "Delete", and fees came back as 0.06929999999999992.

## Decisions
- Bad query with a valid key: charged the full 5 units, no venue budget. One price per /cost
  request; a cheaper error path would be a cheaper way to make a database write. The shared venue
  budget only counts requests that can read a book. The 400 carries the rate-limit headers.
- Money per venue rather than Kalshi's 4 decimals everywhere: Polymarket's fee is defined to 5
  decimals, and 4 would change it.
- Key box: matched by key id, not by the 10-character prefix (only 4 random characters).
- No node test for the auth order: it lives in the route handler, which needs the database and
  Next's path alias. Checked instead on `next build && next start`: /cost with no key, a malformed
  header or an unknown key → 401, with and without a bad query; the other four routes → 401.

## Follow-ups
- Not checked with a real key (needs a signed-in session): the rounded 200 answer and the 400
  with rate-limit headers. Worth one curl after deploy.
- An unknown contract (404) still takes a venue-budget slot, as before.
- Review nits fixed: 404 answers from /cost carry the rate-limit headers like 200/400/409; `round()` rounds halves away from zero (1.005 → 1.01) and never returns -0.
